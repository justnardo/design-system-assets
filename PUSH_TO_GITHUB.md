# Push to GitHub — step by step

The repo is fully initialized: README, LICENSE, .gitignore, CONTRIBUTING.md, all 23 source files, and one clean initial commit on the `main` branch. You just need to create the GitHub repo on your end and push.

## Step 1 — Download and extract the tarball

Download `design-system-assets-repo.tar.gz` from this conversation, then on your machine:

```bash
mkdir design-system-assets
cd design-system-assets
tar xzf ~/Downloads/design-system-assets-repo.tar.gz
ls -la   # confirm you see .git/, README.md, scripts/, etc.
```

## Step 2 — Verify the commit looks right

```bash
git log --oneline
# expected output:
# ebc4015 Initial release: design-system-assets v1.2

git status
# expected: "nothing to commit, working tree clean"
```

If anything looks off, stop here and ping me before pushing.

## Step 3 — Verify the author (already set, but worth confirming)

The tarball is committed as `Just_Nardo <Just_Nardo@users.noreply.github.com>`. That should match your GitHub username. Confirm with:

```bash
git log --pretty=format:"%an <%ae>" -1
# expected: Just_Nardo <Just_Nardo@users.noreply.github.com>
```

The `users.noreply.github.com` email is GitHub's privacy-protecting placeholder — it links commits to your account without exposing a real email. If you'd rather use your real email, run:

```bash
git config user.email "your-real-email@example.com"
git commit --amend --reset-author --no-edit
```

## Step 4 — Create the GitHub repo

Two options:

**Option A — using the GitHub web UI (no CLI needed):**

1. Go to https://github.com/new
2. Repository name: `design-system-assets`
3. Description: "A Claude Code skill that reads your design system first, then generates brand-aware visual assets"
4. Public
5. **Do NOT** initialize with README, .gitignore, or LICENSE — you already have all three. Leave those checkboxes empty.
6. Click "Create repository"
7. Copy the URL it shows you (something like `https://github.com/YOUR-USERNAME/design-system-assets.git`)

**Option B — using the GitHub CLI:**

```bash
gh repo create design-system-assets --public --source=. --description "A Claude Code skill that reads your design system first, then generates brand-aware visual assets"
```

This creates the repo AND pushes in one step. If you go this route, skip Step 5.

## Step 5 — Push (only if you used Option A)

```bash
git remote add origin https://github.com/YOUR-USERNAME/design-system-assets.git
git push -u origin main
```

If GitHub asks for credentials, use a personal access token (not your password) — passwords haven't worked since 2021. Create one at https://github.com/settings/tokens with `repo` scope.

Once the repo is live, search for "awesome-claude-code" or similar community skill directories on GitHub. Most accept PRs that add a single line linking to your repo with a short description. This is where most people will discover your skill.

## What to do BEFORE you push (recommended)

1. **Skim the README** one more time and adjust the "Built by" section — the placeholder says "First Glance Bahamas". If you want a personal byline or a different agency framing, change it before the first push. Easier to edit before the repo has stars than after.
2. **Decide on the org/user.** Do you want this under a personal GitHub account or a `firstglance` org? If you go with the org, create the org first, then create the repo under it.
3. **The `.skill` file is gitignored.** That's intentional — `.skill` files are build artifacts, not source. Users will install via clone-and-extract. If you want them to be able to download a packaged `.skill` directly, you'll need to publish it as a GitHub Release after the initial push (see Step 8).

## Step 8 — Create the first release (optional)

After the first push:

```bash
git tag v1.2.0
git push origin v1.2.0
```

Then on GitHub, go to the "Releases" tab and create a release from that tag. Upload the `design-system-assets.skill` file as a release asset. Now users can download a packaged installable directly from the Releases page without having to clone and re-package.

## When something goes wrong

**"Updates were rejected because the remote contains work..."** — you initialized the GitHub repo with a README/LICENSE/etc. Either delete the GitHub repo and recreate it WITHOUT those checkboxes (Step 4), or run `git pull --rebase origin main` to merge GitHub's autogenerated files in first.

**"Authentication failed"** — you tried to push with your password. GitHub disabled password auth in 2021. Create a personal access token at https://github.com/settings/tokens with `repo` scope and use that as the password when prompted.

**"Remote: Repository not found"** — the URL is wrong, or the repo is in a different org. Run `git remote -v` to check what remote you've set, and `git remote set-url origin <correct-url>` to fix.
